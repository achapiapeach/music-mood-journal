# 노래로 남긴 마음 · 음악 감정 일기

YouTube Music 시청 기록(Google Takeout의 `watch-history.json`)을 분석해 **언제, 무엇을, 얼마나 반복해서 들었는지** 보여주고, 그 노래를 듣던 순간의 **마음**을 표준화된 기준으로 기록한 뒤, 그 기록으로 **곡을 추천**하는 웹 앱입니다.

- 빌드 없음 — `index.html` **한 파일**로 동작 (HTML + CSS + JS, 외부 의존성 0)
- 서버 없음 — 올린 파일은 어디로도 전송되지 않고 브라우저 안에서만 처리
- 이 저장소에는 **어떤 사람의 시청 기록도 들어 있지 않습니다.** 처음 열면 비어 있고, 각자 자기 기록을 올려 씁니다.

**바로 쓰기 → https://achapiapeach.github.io/music-mood-journal/**

*(지각 = 곡이 표현하는 감정 / 유발 = 듣는 사람이 실제로 느낀 감정)*

### 조사에서 얻은 세 가지

1. **축은 두 개로 충분히 통한다.** DEAM·AMG1608·PMEmo·K-Pop 데이터셋 모두 **긍정도(valence) × 에너지(arousal)** 두 축을 씁니다. Russell(1980)의 *circumplex model of affect* 이후 이 분야의 사실상 표준입니다. → 우리도 이 축을 그대로 씁니다.
2. **그러나 라벨은 대부분 ‘곡이 표현하는 감정’이다.** DEAM·AMG1608·4Q·MIREX는 *지각된* 감정, Emotify·PMEmo·DEAP만 *유발된* 감정입니다. **‘내가 이 곡을 들으며 실제로 느낀 것’을 시간·상황과 함께 모은 데이터는 드물어요.** 우리 기록이 채우는 빈칸이 여기입니다.
3. **사람마다 다르게 느끼고, 한 사람의 판단도 흔들린다.** AMG1608의 평가자 간 일치도는 Krippendorff's α 0.31(긍정도)·0.46(에너지)로 ‘보통(fair)’ 수준이었고, DEAM도 “긍정도 라벨의 품질이 에너지보다 낮다”고 밝힙니다. → **여러 참여자**와 **확신도**가 필요합니다. 교수님이 지적한 신뢰성 문제가 바로 여기서 나옵니다.

> 참고: K-Pop 데이터셋 연구는 한국인과 미국인 청취자가 같은 곡에 다른 기분 라벨을 붙인다는 것을 보여 줍니다(한국인은 ‘명랑·서정·익살’을, 미국인은 ‘열정·공격’을 더 자주 선택). 문화·언어 맥락이 라벨에 들어가므로, 우리 기준도 **우리말 감정 어휘**로 두는 편이 타당합니다.

## ② 우리가 정한 기분 분류 기준

### 2축 4사분면 + 우리말 감정 8개

- **가로축 긍정도(Valence)** −1(불쾌) ~ +1(쾌)
- **세로축 에너지(Arousal)** −1(이완) ~ +1(각성)

| 사분면 | 이름 | 감정 쌍 | 우리 감정 |
| --- | --- | --- | --- |
| **Q1** (＋긍정, ＋에너지) | 활기 | 기쁨 · 들뜸 | 😊 행복(+0.75/+0.45), 💗 설렘(+0.65/+0.80), 🎧 집중(+0.10/+0.45) |
| **Q2** (−긍정, ＋에너지) | 긴장 | 분노 · 초조 | 🔥 화남(−0.70/+0.75) |
| **Q4** (＋긍정, −에너지) | 잔잔함 | 평온 · 그리움 | 🌿 평온(+0.60/−0.65), ☁️ 몽글몽글(+0.45/−0.25) |
| **Q3** (−긍정, −에너지) | 가라앉음 | 우울 · 지침 | 🌧️ 우울(−0.65/−0.55), 🥲 지침(−0.15/−0.70) |

감정마다 **좌표(v, a)** 가 고정되어 있어서, 감정을 고르면 자동으로 사분면과 좌표가 계산됩니다(여러 개를 고르면 평균). 이 좌표가 통계와 추천의 공통 언어가 됩니다.

### 왜 8개인가

- 공개 데이터셋의 라벨(4사분면, MIREX 5클러스터, GEMS 9감정)을 우리말 일상어로 옮기되, **한국어로 자연스럽게 구분되는 강도·결**을 살렸습니다. ‘몽글몽글’·‘지침’처럼 기존 데이터셋에 잘 없는 한국어 감정 결도 포함했습니다(문화 간 라벨 차이 연구를 반영).
- 4사분면만 쓰면 “우울”과 “지침”이 같은 칸에 묶여 추천이 거칠어지고, 너무 잘게 나누면 참여자마다 해석이 달라집니다. **8개 + 복수 선택**이 그 사이의 균형점입니다.

### 라벨 단위: 곡이 아니라 ‘사람 × 곡 × 시점’

기존 데이터셋은 대부분 **곡 하나에 감정 하나**를 붙입니다. 우리 라벨은 **한 참여자가 한 곡을 한 번 들은 시점**입니다.
그래서 같은 곡이 사람마다, 날마다 다른 좌표를 가질 수 있고, 그것이 곧 “이 사람에게 이 곡이 하는 일”이 됩니다.

### 표준화된 체크 절차 (6단계)

1. **언제** — 날짜 + 시간대(새벽 0–6 / 아침 6–12 / 오후 12–18 / 저녁 18–24)
2. **어떤 곡** — 시청 기록에서 고르거나 직접 입력
3. **어느 칸** — “기분이 좋았나/나빴나”, “몸과 머리가 활기찼나/가라앉았나”로 사분면을 정하고 그 칸의 감정을 1개 이상 선택
4. **얼마나 강했나** — 1(아주 옅게) ~ 5(아주 진하게)
5. **어떤 상황** — 이동·출퇴근 / 공부·작업 / 운동·산책 / 휴식 / 잠들기 전 / 사람들과 / 혼자 / 일·아르바이트 / 그 외 (복수)
6. **얼마나 확신하나** — 확실해요(1.0) / 그런 편이에요(0.7) / 잘 모르겠어요(0.4)

확신도는 단순 설문 항목이 아니라 **가중치**입니다. 통계의 분포와 추천 점수에서 기록 하나의 무게로 쓰입니다(`무게 = 확신도 × (0.6 + 0.1 × 강도)`).

## ③ 다중 참여자 데이터 수집 구조

### 흐름

```
참여자 각자: 사이트 접속 → (선택) watch-history.json 업로드 → 기분 기록
                ↓
        연구 데이터 › ① 라벨 데이터 내보내기 (JSON 또는 CSV)
                ↓  (카톡·메일로 파일 전달)
연구자(나): 연구 데이터 › ② 친구 파일 합치기 (여러 개 한 번에)
                ↓
        ③ 통합 통계: 참여자 수 · 라벨 수 · 감정/사분면/시간대/맥락 분포 · 참여자별 표
                ↓
        추천 탭이 내 기록 + 통합 데이터를 함께 사용
```

- 서버가 없으므로 **파일이 곧 데이터 전달 수단**입니다. 계정·로그인·업로드 서버가 없어 윤리 검토도 단순합니다.
- 중복 방지: 같은 참여자의 파일을 다시 불러와도 `id` + 내용 해시(`날짜|시간대|곡|아티스트|감정|강도`)로 걸러 **새 기록만** 합칩니다.
- 참여자 구분은 **익명 코드**(`p_xxxxxx`, 브라우저에서 자동 생성)입니다. 별명은 선택이고, **내보낼 때 포함할지 스위치**로 정합니다(기본: 코드만).

### 내보내는 항목 (JSON `format: "mmj.labels"`, version 2)

| 필드 | 예 | 설명 |
| --- | --- | --- |
| `participant` | `p_a1b2c3` | 익명 참여자 코드 (별명은 선택) |
| `date` / `slot` | `2026-11-20` / `evening` | 날짜, 시간대 |
| `song` / `artist` | `Night Bus` / `문라이트 클럽` | 곡·아티스트 이름만 |
| `moods` / `moodLabels` | `["blue"]` / `["우울"]` | 감정 id와 한국어 라벨 |
| `quadrant` | `Q3` | 사분면 (파생) |
| `valence` / `arousal` | `-0.65` / `-0.55` | 좌표 (파생, 감정 평균) |
| `intensity` | `3` | 강도 1–5 |
| `confidence` / `confidenceWeight` | `high` / `1.0` | 확신도와 가중치 |
| `contexts` | `["move","alone"]` | 듣던 맥락 |
| `memo` | *(기본 제외)* | 체크했을 때만 포함 |

**나가지 않는 것**: `watch-history.json` 원본, 실제 시청 시각(초 단위), 곡 재생 길이, 계정 정보, 브라우저에 저장된 다른 기록, 샘플 기록.
CSV는 엑셀에서 바로 열리도록 UTF-8 BOM을 붙입니다. **라벨 기준(코드북)** 도 JSON으로 내보낼 수 있어, 참여자마다 같은 정의를 쓰도록 맞출 수 있습니다(감정별 좌표·맥락·확신도·파생 필드 규칙 포함).

### 통합 통계가 보여 주는 것

- 참여자 수 / 기록 수 / 감정 라벨 수 / 라벨이 붙은 곡 수
- 감정별 분포(8개), 사분면별 분포(Q1–Q4), 시간대·맥락 분포
- 참여자별 표: 기록·곡·라벨 수, 대표 감정, 평균 강도, 평균 확신도, 출처(이 브라우저/친구 파일/예시)
- 예시 참여자 3명을 넣어 보는 버튼으로, 친구 파일이 없어도 통계·추천이 어떻게 달라지는지 시연할 수 있습니다(예시 데이터는 통계에 ‘예시’로 표시되고 내보내기에 포함되지 않음).

## ④ 기록 기반 추천 로직

### 입력

- 지금 기분(감정 1개 이상) → 좌표 `(v, a)` = 고른 감정 좌표의 평균
- 방향: **이 기분 이어가기**(목표 = 지금 좌표) / **기분 끌어올리기**(목표 = 긍정도 +0.55, 에너지 +0.40) / **마음 진정시키기**(목표 = 긍정도 +0.25, 에너지 −0.55)
- 데이터: 내 기록 + 불러온 참여자 기록

### 곡 프로필

곡마다 기록된 라벨을 **확신도 × 강도**만큼 무겁게 가중 평균해 “이 곡을 들을 때의 좌표” `(곡 v, 곡 a)`를 만듭니다. 같은 곡에 상반된 기록이 쌓이면 좌표가 가운데로 모여, 그 곡이 ‘양가적’이라는 사실이 드러납니다.

### 점수

```
일치도  = 1 − ( |목표v − 곡v| + |목표a − 곡a| ) / 2       # 0~1
근거두께 = min(1, ln(1 + Σ무게) / ln 6)
시간대   = 지금 시간대(새벽/아침/오후/저녁)에 들었던 비중 × 0.05
참여자가점 = (기록한 사람 수 − 1) × 0.025 (최대 0.05)

점수 = 일치도 × 0.60 + 근거두께 × 0.22 + 시간대 + 참여자가점
```

### 추천 이유를 함께 보여 준다

결과 카드마다 근거를 문장으로 표시합니다.

- “**우울·지침** 기분으로 3번 들은 곡 · 2명이 기록”
- “곡의 좌표 **긍정도 −0.62 · 에너지 −0.48** — 목표와 일치 **74%**”
- “주로 **이동·출퇴근** 때 들었어요”
- “지금 시간대(저녁)에 들은 기록 2건”
- “확신도 ‘확실해요’ 기록 2건”
- “지금보다 **차분한 쪽**으로 고른 곡이에요”

점수가 높아도 근거가 얇으면(기록 1건, 확신도 낮음) 순위가 내려갑니다. **설명할 수 없는 추천은 하지 않는 것**이 이 설계의 원칙입니다.

### 콜드 스타트

- 라벨이 하나도 없으면: 시청 기록에서 **가장 많이 반복한 곡**을 대신 보여 주고, 라벨이 쌓이면 기분 기반으로 바뀐다고 안내합니다.
- 시청 기록도 없으면: ‘기분 기록’ 탭에서 두세 번만 남겨 보라는 안내와 함께 **샘플로 둘러보기** 경로를 제시합니다.
- 추천 화면 아래 **커버리지 바**가 “시청 기록 N곡 중 몇 %에 라벨이 붙었는지”를 보여 줘서, **기록이 쌓이는 만큼 추천이 좋아진다**는 것을 눈으로 확인할 수 있습니다. — 이것이 “기록하는 시스템의 당위성”에 대한 답입니다.

## 개인정보와 윤리

- 업로드한 `watch-history.json`은 `FileReader`로 **브라우저 안에서만** 파싱되고 네트워크로 나가지 않습니다.
- 기록은 그 브라우저의 `localStorage`에만 저장됩니다. 서버·계정·분석 도구가 없습니다.
- 연구용 내보내기는 **연구에 필요한 최소 항목**만 담고, 원본 시청 기록·정확한 시청 시각·메모를 기본으로 제외합니다.
- 참여자는 언제든 자기 기록을 지우거나(기록 모두 지우기), 코드를 새로 만들 수 있습니다.
- 친구 파일을 불러와도 **그 사람 기록은 다시 내 파일로 나가지 않습니다**(참여자마다 자기 파일을 따로 내보내야 함).

## 화면

- **분석** — 전체 재생 수, 고유 곡 수, 최다 청취 시간대, 최다 아티스트 / 시간대별 막대 차트 / 반복 청취 TOP 15 / 아티스트 TOP 10
- **기분 기록** — 분류 기준(사분면 지도) + 6단계 체크 폼 + 타임라인(수정·삭제)
- **모아보기** — 감정별로 묶어 그 마음이었을 때 들은 곡과 메모
- **추천** — 지금 기분·방향 선택 → 근거가 붙은 추천 5곡 → 바로 기록으로 이어짐
- **연구 데이터** — 참여자 코드/별명, 라벨 내보내기(JSON·CSV·코드북), 친구 파일 합치기, 통합 통계, 기준과 데이터셋 조사 표

## 쓰는 법

1. [takeout.google.com](https://takeout.google.com) → **모두 선택 해제** 후 **YouTube 및 YouTube Music**만 선택
2. **여러 형식** → `history` 항목을 **JSON**으로 변경
3. 내보내기 → ZIP 압축 해제 → `Takeout/YouTube and YouTube Music/history/watch-history.json`
4. 사이트에서 **내 watch-history.json 올리기**
5. 같은 사이트에서 곡과 마음을 기록 → **연구 데이터** 탭에서 JSON으로 내보내 친구·연구자에게 전달

기록이 없어도 **샘플로 둘러보기**로 화면 전체(추천 포함)를 먼저 볼 수 있습니다.
